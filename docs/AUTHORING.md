# 작성 규칙 (모듈 저자용)

모든 모듈은 이 규칙을 따른다. 검증 에이전트는 이 문서를 기준으로 PR을 심사한다.

## 1. 디렉터리 구조

```
curriculum/mNN-<slug>/
├── README.md              # 모듈 개요: 목표, 시나리오 단계, 레슨 목록, 실습 등급표, 예상 시간
├── 01-<lesson-slug>.md    # 레슨 (개념 + 실습 안내가 한 문서에)
├── 02-...md
├── labs/
│   ├── lab01-<slug>.sh    # 레슨의 실습을 처음부터 끝까지 재현하는 스크립트
│   ├── ...
│   └── verify.sh          # 모듈의 모든 lab을 깨끗한 에뮬레이터에서 실행·검증
├── sdk/
│   └── <name>.py          # boto3 예제 (uv run 으로 실행)
├── cheatsheet.md          # 비교표·한계값·시험 포인트 요약
└── quiz.md                # 시나리오형 문제 10문항 이상 + 해설
```

공용 파일(`scripts/`, `tools/`, `docs/`, 루트 `README.md`, `pyproject.toml`)은 **자기 역할이 아니면 수정하지 않는다.** 필요하면 PR 본문에 요청 사항으로 적는다.

## 2. 레슨 문서 형식

```markdown
# M03-05. 로드 밸런서
> 도메인: D2, D3 · 예상 시간: 50분 · 실습 등급: 🟡

## 왜 필요한가        ← TodayOrder 시나리오의 문제 상황 2~4문장
## 핵심 개념          ← 주니어 눈높이. 비유 1개 이하, Mermaid 다이어그램 권장
## 직접 해 보기       ← 명령 → 실제 출력 → "방금 본 것" 해설의 반복
## 실제 AWS에서는     ← 에뮬레이터와 다른 점, 재현 안 되는 동작
## 시험 포인트        ← 불릿 3~7개. "X가 나오면 Y" 형태
## 스스로 확인        ← 서술형 질문 2~3개 (답은 <details>)
```

- 문서는 **한국어**. 서비스명·API명·CLI는 영문 원문 유지 (예: "보안 그룹(Security Group)" 첫 등장 시 병기).
- 한 레슨은 20~60분 분량. 길어지면 나눈다.
- 다이어그램은 Mermaid (GitHub에서 렌더링됨). 이미지 파일을 만들지 않는다.
- 용어는 처음 나올 때 한 줄로 정의한다. 독자는 HTTP·SQL·Linux 기본은 알지만 AWS는 처음이다.

## 3. 실습 규칙 (가장 중요)

1. **실제 실행한 출력만 싣는다.** 문서의 명령 블록과 출력 블록은 에뮬레이터에서 실행한 결과를 그대로(길면 `...`로 생략 표시) 싣는다. 임의로 만든 ID·출력 금지.
2. **등급은 실행 결과로 정한다.** `docs/FIDELITY.md`를 먼저 보고, 직접 실행해 🟢/🟡/🔴를 확정한다. `501 NotImplemented`나 AWS와 다른 동작을 만나면 숨기지 말고 그대로 보여 주고 "실제 AWS에서는"에 차이를 쓴다.
3. **미구현을 만나면** 우회 실습으로 대체하고(예: 설정값 조회, 로컬 Python 실행, 워크시트), 모듈 README의 "에뮬레이터 제약" 절에 오퍼레이션명과 증상을 기록한다.
4. **스크립트는 멱등·자급자족.** 각 `labNN-*.sh`는 `set -euo pipefail`, `source "$(git rev-parse --show-toplevel)/scripts/env.sh"`로 시작하고, 깨끗한 에뮬레이터에서 단독 실행 가능해야 한다(앞 lab에 의존하면 스크립트 안에서 선행 리소스를 직접 만든다). 끝에 핵심 결과를 단언(assert)한다.
5. **`verify.sh`** 는 모듈의 모든 lab과 sdk 예제를 실행하고, 전부 통과하면 `MODULE mNN OK`를 출력하며 0으로 종료한다. 🔴 등 실행 불가 항목은 `SKIP(사유)`로 표시한다.
6. **리소스 이름**은 `todayorder-` 접두사. 리전은 `us-east-1` 고정. 계정 ID는 `000000000000`.
7. **boto3 예제**는 타입 힌트와 `if __name__ == "__main__":`을 갖춘 실행 가능한 단일 파일. 엔드포인트·자격 증명을 코드에 하드코딩하지 않는다(환경 변수로 주입 — 실제 AWS에서도 그대로 동작하는 코드여야 한다).
8. 실제 AWS 자격 증명·계정을 절대 사용하지 않는다. 모든 실행 전 `aws sts get-caller-identity`의 Account가 `000000000000`인지 env 스크립트가 보장한다.

## 4. 내용 정확성

- 한계값·수치(예: Lambda 15분, SQS 메시지 256KB, S3 객체 5TB)는 확신이 없으면 AWS 공식 문서로 확인한다. 확인 못 한 수치는 쓰지 않는다.
- SAA-C03 범위를 벗어난 깊이(예: 특정 API의 모든 파라미터)는 피한다. 시험이 묻는 것은 "선택"이다.
- 퀴즈는 **자체 제작**만. 실제 시험 문제·덤프 문제를 옮기지 않는다. 문항마다 정답 근거와 오답이 틀린 이유를 쓴다.
- 폐기·개명된 서비스명에 주의 (예: AWS SSO → IAM Identity Center, OAI → OAC 권장).

- 브랜치: [AGENTS.md](./AGENTS.md)에 지정된 **역할 브랜치명**을 그대로 쓴다. `main`에 직접 푸시 금지.
