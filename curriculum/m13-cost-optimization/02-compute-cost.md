# M13-02. 컴퓨트 비용: 구매 옵션 조합, 적정 크기, 스팟, Graviton
> 도메인: D4 · 예상 시간: 50분 · 실습 등급: 🟢 인벤토리 읽기 / 🔴 실제 청구 금액

## 왜 필요한가

TodayOrder 청구서에서 가장 큰 줄은 EC2다. API 서버 4대는 1년 내내 켜져 있고, 정산 배치 서버 6대는 매일 밤 8시간 돈다. 전부 **온디맨드**로 사고 있다. "1년은 확실히 쓸 서버"와 "밤에만 도는, 끊겨도 다시 돌리면 되는 서버"에 같은 값을 내는 것은 낭비다. 이 레슨은 워크로드의 성격에 따라 구매 방법을 섞는 법을 배운다. M03 레슨 2에서 배운 구매 옵션을 **돈의 언어**로 다시 본다.

## 핵심 개념

### 구매 옵션 한 장 요약

| 옵션 | 무엇을 약속하나 | 할인(AWS 공식 "최대") | 맞는 워크로드 | 주의 |
|---|---|---|---|---|
| 온디맨드 | 없음 | 0% | 짧은·예측 불가·처음 보는 워크로드 | 가장 비싸지만 가장 유연 |
| **Compute Savings Plans** | 1년/3년 동안 **시간당 사용 금액($/h)** | 최대 66% | 꾸준한 사용, 인스턴스 패밀리·리전·OS가 바뀔 수 있음. **Fargate·Lambda에도 적용** | 약정 금액은 안 써도 낸다 |
| **EC2 Instance Savings Plans** | 1년/3년, **특정 리전의 인스턴스 패밀리** | 최대 72% | 패밀리(예: m7i)가 고정된 꾸준한 사용 | 패밀리를 바꾸면 할인 안 됨 |
| 예약 인스턴스(RI) | 1년/3년, 인스턴스 속성 | 최대 72% | 위와 비슷. 시험에는 아직 자주 나옴. RDS·ElastiCache·Redshift 등은 "예약"이 주된 할인 방법 | 새 EC2 약정은 Savings Plans 권장 |
| **스팟** | 없음 (남는 용량) | 최대 90% | **중단돼도 되는** 배치·CI·렌더링·빅데이터·상태 없는 웹 | 2분 전 중단 알림 후 회수될 수 있다 |
| 온디맨드 용량 예약 | 특정 AZ의 용량 | 할인 없음(SP·RI와 함께 쓰면 할인) | "그 날 그 AZ에 반드시 N대" | 안 써도 낸다 |
| 전용 호스트 / 전용 인스턴스 | 물리 서버 | — | 소켓·코어 단위 라이선스(BYOL), 규정 | 가장 비쌈 |

결제 방식은 선결제 전부/일부/없음. **선결제가 많고 기간이 길수록 할인이 크다.**

### 섞어 쓰는 법: "바닥은 약정, 출렁임은 온디맨드, 끊겨도 되는 건 스팟"

TodayOrder API 서버 대수 (하루):

| 시각 | 0시 | 3시 | 6시 | 9시 | 12시 | 15시 | 18시 | 21시 |
|---|---|---|---|---|---|---|---|---|
| 필요 대수 | 6 | 6 | 6 | 8 | **12** | 9 | **12** | 8 |
| 바닥(약정) | 6 | 6 | 6 | 6 | 6 | 6 | 6 | 6 |
| 피크(온디맨드) | 0 | 0 | 0 | 2 | 6 | 3 | 6 | 2 |

- 바닥(6대) = 하루 종일 꺼지지 않는 **바닥(baseline)** → Savings Plans로 덮는다.
- 바닥 위 = 점심·저녁 피크 → Auto Scaling이 띄우는 **온디맨드**.
- 표 밖의 정산 배치 → **스팟**(Auto Scaling 그룹의 혼합 인스턴스 정책이나 EC2 Fleet으로, 여러 인스턴스 유형·AZ에 분산해 중단 위험을 줄인다).

**약정은 피크가 아니라 바닥에 맞춘다.** 피크에 맞춰 약정하면 피크가 아닌 시간에 쓰지 않는 약정 금액을 그대로 낸다(워크시트 2에서 숫자로 확인).

### 적정 크기(right-sizing)와 Graviton

- **적정 크기**: CPU 10%로 도는 `m7i.2xlarge`는 `m7i.large`로 충분할 수 있다. 크기를 반으로 줄이면 요금도 대략 반이다. 판단 근거는 CloudWatch 지표(메모리는 CloudWatch 에이전트가 있어야 보인다)와 **AWS Compute Optimizer**의 권장 사항(레슨 5). **약정보다 적정 크기를 먼저** 한다 — 큰 인스턴스에 3년 약정을 걸면 낭비가 3년 동안 고정된다.
- **Graviton(Arm 기반 AWS 프로세서)**: `m7g`, `c7g`처럼 이름에 `g`가 붙는다. AWS는 비교 가능한 x86 대비 "최대 40% 더 나은 가격 대비 성능"을 내세운다(워크로드마다 다르다). 인터프리터 언어(Java, Python, Node.js)나 컨테이너는 옮기기 쉽고, x86 전용 바이너리·라이브러리가 있으면 다시 빌드해야 한다. Lambda·Fargate·RDS·ElastiCache에도 Graviton 옵션이 있다.
- **끄기**: 개발·스테이징 서버를 업무 시간(주 5일 × 12시간 = 월 약 260시간)에만 켜면 730시간 대비 약 64%가 준다. EventBridge Scheduler나 Instance Scheduler로 자동화한다.

### 스팟을 안전하게 쓰는 법

- 중단 알림(2분 전)은 인스턴스 메타데이터와 EventBridge 이벤트로 온다 → 작업을 체크포인트하고 큐에 되돌린다.
- **여러 인스턴스 유형·여러 AZ**에 분산하고, 할당 전략은 `price-capacity-optimized`(가격과 회수 가능성 모두 고려)를 쓴다.
- SQS 큐에서 일감을 가져오는 워커(M06)는 스팟과 궁합이 좋다: 인스턴스가 사라지면 가시성 타임아웃이 지난 메시지를 다른 워커가 처리한다.

### 워크시트 2: 구매 옵션 조합 (손으로)

예시 단가 `m7i.large` 0.10 USD/시간, Savings Plans 할인 30%, 스팟 할인 70%(모두 **예시 숫자**). 한 달 730시간.

- API 바닥 6대 × 730시간
- 피크 추가 6대 × 하루 6시간 × 30일 = 180시간
- 정산 배치 4대 × 하루 8시간 × 30일 = 240시간 (중단되면 처음부터 다시 돌리면 됨)

**문제.** (1) 전부 온디맨드 (2) 바닥만 SP + 피크 온디맨드 + 배치 스팟 (3) 피크까지 12대를 SP로 24시간 약정 + 배치 스팟 — 세 안의 월 비용을 구하라.

<details><summary>정답과 풀이</summary>

| 안 | 계산 | 월 비용 |
|---|---|---|
| (1) 전부 온디맨드 | 6×730×0.10 = 438.0 + 6×180×0.10 = 108.0 + 4×240×0.10 = 96.0 | **642.00** |
| (2) 바닥 SP + 피크 OD + 배치 스팟 | 6×730×0.07 = 306.6 + 108.0 + 96.0×0.3 = 28.8 | **443.40** |
| (3) 12대를 SP로 | 12×730×0.07 = 613.2 + 28.8 | **642.00** |

(3)은 할인을 받았는데도 전부 온디맨드와 같다. 피크용 6대분 약정(6×730×0.07 = 306.6)은 실제로는 180시간만 쓰는데 730시간분을 내기 때문이다. **약정은 바닥에 맞춘다.**

- API 서버 `m7i.large` 4대, 태그 `workload=steady`
- 정산 배치 `c7i.xlarge` 6대, 태그 `workload=batch`, `hours-per-month=240`
- gp2 200 GiB 볼륨 4개, NAT 게이트웨이 1개(태그 `monthly-gb=1000`), 연결하지 않은 탄력적 IP 1개

방금 본 것:

- [`sdk/cost_estimator.py`](./sdk/cost_estimator.py)는 `describe_instances`·`describe_volumes`·`describe_nat_gateways`·`describe_addresses`의 **구성과 태그만** 읽었다. 요금 API는 하나도 부르지 않았다.
- API 서버: 73.00(0.10×730) → 40.88(0.08×730×0.7). Graviton으로 바꾸고 바닥을 Savings Plans로 덮었다.
- 배치: 43.20(0.18×240) → 12.96. 스팟 70% 할인.
- gp2 → gp3: 20.00 → 16.00. 같은 크기에서 gp3는 기본 3,000 IOPS·125 MiB/s를 크기와 관계없이 준다. 볼륨을 붙인 채로 유형을 바꿀 수 있다(Elastic Volumes).
- NAT 줄 90.15 = 시간 요금 36.50(0.05×730) + 처리 요금 50.00(1,000 GB×0.05) + **NAT에 붙은 퍼블릭 IPv4 주소 3.65**(0.005×730). 실제 AWS도 퍼블릭 IPv4 주소를 NAT 요금과 별도로 청구하므로, 추정기는 이 IP를 NAT 줄에 넣어 한 번만 센다.
- 연결 안 된 IP 3.65 → 0. 작지만 "아무 일도 안 하는데 내는 돈"의 전형이다.
- NAT는 그대로다. 이 줄을 줄이는 방법은 레슨 4.
- 태그(`workload`)가 없으면 추정기는 판단을 보류한다. **태그가 곧 비용 분석의 재료**라는 점이 레슨 5로 이어진다.

## 실제 AWS에서는

- 실제 할인율은 인스턴스 유형·리전·기간·선결제에 따라 다르고, 스팟 가격은 수시로 바뀐다. **Savings Plans 구매 권장 사항**(Cost Explorer)과 **Compute Optimizer**가 실제 사용량으로 "얼마를 약정하면 얼마 절감"을 계산해 준다. 에뮬레이터에서는 둘 다 쓸 수 없다(`GetSavingsPlansPurchaseRecommendation`·`GetRightsizingRecommendation` 501, Compute Optimizer는 옵트인 필요 응답).
- 인스턴스 유형 변경(적정 크기)은 인스턴스를 **중지 → 유형 변경 → 시작**한다. 에뮬레이터는 `ModifyInstanceAttribute`가 501이라 실습하지 않았다(M03 참고).

**실제 AWS에서 해 보려면**: 프리 티어 계정의 Billing 콘솔 → Savings Plans → **Recommendations**에서 지난 7·30·60일 사용량 기반 권장 사항을 볼 수 있다(조회 무료, 구매는 되돌릴 수 없으니 **누르지 말 것**). 스팟은 `t3.micro` 하나를 `--instance-market-options MarketType=spot`으로 띄워 요금 차이를 볼 수 있지만 프리 티어 대상이 아니다. 끝나면 `aws ec2 terminate-instances`로 정리한다.

## 시험 포인트

- "1년 이상 꾸준히, 인스턴스 패밀리·리전이 바뀔 수 있음, Lambda·Fargate도" → **Compute Savings Plans**. "패밀리 고정, 최대 할인" → **EC2 Instance Savings Plans**(또는 RI).
- "중단돼도 되는 배치, 가장 저렴" → **스팟**. "중단되면 안 됨" 조건이 보이면 스팟 보기를 지운다.
- "특정 AZ에 반드시 용량 확보, 약정 기간 없이" → **온디맨드 용량 예약**.
- "기존 서버 소켓 단위 라이선스(BYOL)" → **전용 호스트**.
- 약정은 **바닥**에, 피크는 Auto Scaling 온디맨드에. 적정 크기를 약정보다 먼저.
- Graviton = 같은 성능을 더 싸게. "비용 절감 + 성능 유지 + 코드 호환(인터프리터 언어·컨테이너)"이면 후보.

## 스스로 확인

1. RDS에는 Savings Plans가 적용되는가? 꾸준히 도는 RDS 인스턴스의 비용을 줄이는 대표적인 약정 방법은?
2. 회사가 3년 Compute Savings Plans로 시간당 20 USD를 약정했다. 어느 달 실제 사용량이 시간당 15 USD 상당이었다. 그 달은 얼마를 내는가?
3. 스팟 인스턴스로 SQS 큐의 주문 이미지를 처리하는 워커를 돌린다. 인스턴스가 회수되면 처리 중이던 메시지는 어떻게 되는가?

<details><summary>답</summary>

1. Compute·EC2 Instance Savings Plans는 RDS에 적용되지 않는다. RDS의 전통적인 약정 할인은 **예약 DB 인스턴스(Reserved DB Instances)**다. 2025년 12월에는 RDS·Aurora·DynamoDB·ElastiCache 등에 쓰는 **Database Savings Plans**(AWS 발표 기준 최대 35%)도 나왔다. 같은 워크로드에 RDS 예약 인스턴스와 겹쳐 받을 수는 없다. 시험 문제는 오랫동안 "꾸준한 RDS → 예약 인스턴스" 구도로 출제돼 왔다.
2. 약정 금액 20 USD/시간 × 시간을 그대로 낸다. 쓰지 않은 5 USD/시간분은 사라진다. 약정은 "최소 지불 금액"이다.
3. 메시지는 삭제되지 않았으므로 가시성 타임아웃이 지나면 큐에 다시 보이고, 다른 워커가 처리한다(M06). 작업이 멱등이어야 중복 처리가 안전하다.

</details>
